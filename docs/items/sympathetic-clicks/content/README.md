## Spell identity checks

The local test PEQ returned zero references to 44379/44380 across 22 tables before installation. The scan covered all six item spell slots including focus, scroll and worn effects on equipment and augments, all 36 spell effect operands plus recourse/group/description IDs, AA ranks and effects, NPC spell lists and proc fields, auras, traps and persisted player/pet/mercenary spell slots. Both the stock item capture and the retained October 19 production export (308,932 complete items, all six effect slots) returned zero matches. The tracked and local runtime quest trees contained no matching spell literals. Neither the local RoF2 client nor the signed November 12 parent had a row or type-6 description at either ID. These are dated file checks and a local database read.

Checking only the spell table would have misidentified an earlier proposed pair as free. Existing out-of-era gear references the unused definitions, and a later stock scroll references neighboring 44381. The forward migration now rejects a foreign item or spell reference, even where the referenced spell row has never existed. On replay, a saved player buff requires its own verified matching spell. A spellbook entry, memorized spell or pet buff remains a conflict. Repeat the target checks before any future release.

## Server and client definitions

Both click effects require the jewelry to be equipped, use a two-second activation starting at level 1 and have unlimited charges and no reuse timer. Both spells use native permanent formula 50, self target, main buff window, distinct icons and separate spell IDs. Their 12 blank effect slots intentionally contribute no passive stats and cannot trigger the worn sympathetic focus path. Native `Mob::SpellEffect` assigns a buff slot based on duration before dispatching individual effects. Native stacking skips blank slots, and a repeat cast refreshes the same spell. Normal cure/removal, death and saved-buff rules remain authoritative. The direct casting hook owns the numerical gain. The item, spell and QA client must be paired with the matching zone build.

On a qualifying cast, either effect grants 5% of the largest resolved direct hit or heal, rounded down and capped at 48. For example, direct amounts of 19, 40 and 960 yield base bonuses of 0, 2 and 48. Damage uses ordinary target defenses when applying the bonus. Healing computes the amount before overheal, and the recipient's missing health limits what lands. Additional HP components cannot generate a second award.

For an existing QA database, run the guarded `eq-solo-gm/scripts/sympathetic-clicks.sql` alone during the local maintenance window, then refresh both spells and items in the runtime's shared caches and start the matching native consumers. The fresh-install tier bootstrap sources this same migration from `eq-solo-gm/scripts`. SQL compares the click fields and identifying attributes on all eight quality rows, preserves unrelated item attributes, and checks both complete 237-column spell rows and both type-6 descriptions. Its InnoDB transaction rejects an occupied identity or changed click and undoes earlier writes if a late check fails.

To disable item activation, apply `disable.sql` with the same cache pairing. It restores the eight click-related fields on the two items and preserves both spell/text definitions for saved buffs. Existing active buffs can still produce results with the enabled native policy. To stop those results, use the compatible zone's rank cap or remove the two buffs through ordinary gameplay. A later forward application restores both clicks. Keep player inventory, earned tiers and saved buffs intact.
