# 0018: Validate AA caps through native rank-chain projection

Date: 2026-09-13. Status: isolated prototype verified; release integration pending.

## Decision

Prefer the existing native AA data model for the next enforcement implementation:
materialize retained families and capped rank chains from preserved original data.
Test each candidate in the empty isolated database, restore exactly between
candidates, and keep the complete original table backup and generated reversal.
Do not apply a diagnostic combat core to live characters as a finished offering.

## Evidence

The two projections expose exactly 61/109 native ranks, preserve 21 legal build
readouts, reject 14 purchases that succeed before projection, and retain all 12
maximum-AA boss reports byte-for-byte. Both restorations and a deliberately
failed transaction reproduce the complete original AA-table dump. Existing
disabled families stay disabled. The binary and native combat formulas are unchanged.

## Alternatives and consequences

A separate C++ cap table would require guarding every effective-rank consumer,
including passive bonuses and focus effects, as well as purchases and activation.
The tested projection instead uses the loader's existing rank associations.
Native expansion tags alone cannot express the intended early Nightcap exceptions.

Projection still needs complete release offerings, durable original rank data,
owned-rank reconciliation, activation/persistence tests and declarative era
integration. A later expansion must restore original links before applying its
new caps. Existing ownership must not be dropped or overwritten as a side effect
of changing the active catalog. These remain release requirements, not proof
supplied by the empty-fixture experiment.
