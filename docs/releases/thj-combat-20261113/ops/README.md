## Build

The local Docker build root is `/tmp/nightcap-thj-combat-20261113`. Place `native.py`, `prepare.py` and the byte-preserving feature patches there. Run `native.py PROFILE baseline` first. For each candidate run `prepare.py PROFILE PHASE`, then `native.py PROFILE PHASE`. The profiles are `local` and `shipping`. The phases are `bow` and `combined`. Run `collect.py PROFILE PHASE` on Windows to export the build receipt.

The overlay preserves the previously deployed objects, source identities, compiler flags and original virtual paths. It applies only the reviewed feature hunks at zero fuzz after normalizing line endings in the isolated copies. It rebuilds the zone PCH for the changed nonvirtual declarations. ## Recovery

Read each phase’s private durable log and receipts first. A maintenance or state mismatch can halt before any service changes. After a partial activation with admissions closed and no opening receipt, `control.py recover-closed --start` checks the current service identities and returns to the retained predecessor. If it has to restart a game, it takes a new stopped backup and computes the expected boot state from the current database before selecting the original image. It does not replay a session or restore a player snapshot. After opening, use a fresh guarded release based on current state.
