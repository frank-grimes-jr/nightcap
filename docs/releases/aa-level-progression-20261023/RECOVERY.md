# Recovery boundary

Any failed activation/opening keeps gateway and game stopped and retains all
receipts. Inspect that exact attempt; do not rerun activation or restore the
pre-release player snapshot. The backup is disaster recovery evidence, not the
normal rollback mechanism.

Before new-client exposure or access reopening, an explicitly planned old-image
recovery can remove only the release-owned ruleset1 row after checking its exact
value20/notes and the full rules image. Verify the original rules image, use the
retained base image, and run the same current-state/startup/market checks before
reopening. The old world otherwise deletes this unknown rule at boot.

After new-client exposure or player activity, do not silently restore the old
zone: it converts every positive saved/client allocation to100%. A compatible
behavior fallback retains all three new binaries and the signed proxy, changing
only AA:LevelBasedPointsPerLevel from20 to0 under the same locks and a stopped
fresh backup. This restores the legacy XP-priced award path while preserving
percentages and the fixed AA storage units. It is an explicit recovery decision,
not an automatic deployment action. Guard full rule before/after images, preserve
all current character state, and verify the fresh startup before access opens.

Never lower a player's launcher release checkpoint. A client correction is a
new, higher signed release retaining the complete inventory/history. Keep both
immutable release assets and the prior channel as audit/recovery inputs.
